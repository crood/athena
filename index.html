Why Athena

Built from eight months of frustration

Every existing harness does some things brilliantly and others barely at all. Athena started as a personal attempt to build the one that didn't.

Athena is the core. Everything around it extends what Athena can know, where it can exist, and how you can interact with it.

Full context control

Choose exactly which tool schemas are included, what gets sent between turns, and when to compact. No invisible token burn.

Truly model agnostic

Local models, cloud providers, reasoning models, small specialists. Swap freely based on task, speed, privacy, and hardware.

Human-in-the-loop

Sensitive actions can be paused and approved through any connected interface, including from your wrist.

Your data, legible

How information about you is stored and used is not obfuscated. Memory and retrieval are explicit, inspectable, and yours.

Deterministic events

The harness knows what it is doing because it is the one doing it. Tool state, approvals, and activity are sourced from the infrastructure, not the model.

Interfaces fit the moment

Chat is one interface. A knowledge graph is another. A watch. A sheet of e-paper. Athena shouldn't care which one you reach for.

Architecture

The harness is the orchestration layer

Models are interchangeable reasoning components. The harness coordinates everything around them: tools, memory, agents, events, and approvals.

Ecosystem

Companion projects extend Athena's reach

None of these are required for Athena to function. They exist to broaden where Athena can know things, and what you can do from where you are.

Knowledge · Obsidian

Athena Mini

Brings Athena into an Obsidian vault. Semantic retrieval, embeddings, vector search, and a knowledge graph that lights up as Athena reads or edits, because those events originate from real harness operations.

Identity · Memory

Identity Engine

A structured record of daily life, events, decisions, observations. That builds searchable personal history over time. Gives Athena context about the person using it, and gives you a dataset about yourself you can actually query.

Wearable · Galaxy Watch

Watch Companion

Remote approval and system presence on the wrist. When Athena pauses for human confirmation, the request appears on the watch. Also gives Athena an emotive face. A small visual presence that reacts to what the harness is doing.

Documents · e-Paper

reMarkable Companion

File exchange, PDF workflows, and deeper Athena integration on an e-paper device. A quiet, paper-like environment instead of another dashboard, with longer-term interest in handwritten work moving back into Athena.

Design Principles

What guides the build

  • Local first Local models and local data are first-class. Cloud services can be useful, but Athena should not depend on them.
  • Model independence Models change quickly. The surrounding system should survive them.
  • Deterministic infra If the harness already knows something happened, the model shouldn't need to describe it. Events, state, and approvals belong to software.
  • Human control Powerful actions are inspectable and, where appropriate, require explicit approval before they happen.
  • Context is leverage Good retrieval and memory can improve a system more than simply using a larger model.
  • Build to understand Athena is also an experiment. Part of its purpose is exploring how these systems work when individual pieces are exposed, modified, and connected in unusual ways.
